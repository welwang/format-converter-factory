# 四維八德 2.3.4 架構與驗證

本版為 C++20／Python 混合架構。介面保持既有操作方式，離線引擎與三個模型保留。

| 元件 | 職責 |
|---|---|
| Win32／WebView2 外殼 | 真實路徑拖放、原生對話框、單一實例、視窗狀態與完成通知 |
| 原生工作引擎 | 影音、字幕、壓縮、Office、電子書與部分 PDF；工作排程、取消、重試、進度及輸出檢查 |
| 方法註冊層 | 註冊 7 個方法，依方法、工具與選項決定原生處理或轉交 Python |
| Python 背景元件 | 圖片、其餘 PDF、OCR、AI、3D 與其他尚未移植的功能 |

原生 PDF 工具為複製、壓平、無損壓縮、合併、移除、抽取與重排。PDF→PNG 使用 PDFium；PDF→PDF 使用 qpdf，合併頁面使用 PDFium。非無損壓縮、損壞檔修復及圖片等保留既有處理，避免改變輸出或降低可修復範圍。原生工具仍可向 Python 取得使用者選項。

## 驗收條件

- 固定 C 基準修訂 416ab3d。每次完整驗收重新執行基準與 C++，不沿用舊的外殼報告。
- 報告缺失、解析失敗、兩版共同轉檔失敗、外殼零通知、非零結束碼或輸出檔不存在，都必須拒絕通過。
- 只正規化測試路徑、執行期工作代號及工作物件的時間／速度欄位。取消競態的 encoder／output 可不同。外殼通知數量可不同，但各自必須大於零。
- 免重編碼以實際影片測試，要求成功及非空輸出；輸出大小必須與工作記錄一致。
- 方法探針的 python_calls=0 直接驗證 cleanup_scan，不代表所有註冊方法或原生工具完全不呼叫 Python。
- 煙霧測試在隔離候選目錄執行，包含混合 C++／Python 工作、原生 PDF 工作及 Python 轉交工作。受測目錄設定與輸出可被測試寫入。

## 本版修正

Python 回覆緩衝改用堆積配置，避免 1 MB 頁面執行緒堆疊溢位。逐位元複製驗證改用每次呼叫專屬緩衝，避免並行工作互相覆蓋。PDF 驗證文字包含頁數。

詳細執行結果、版本與雜湊以根目錄 TEST_RESULTS.md、PACKAGE_VALIDATION.md 及發布頁的校驗資料為準。指定 24 頁素材的效能量測為原生路徑相對 Python 正式工作路徑 1.11×；這不是所有 PDF 或硬體的固定加速比。

## 平台與範圍

目標為 Windows 10／11 x64，保留 CPU 與省資源模式。實體 4 GB 電腦、所有 Windows 更新與顯示卡驅動仍未完整驗證。圖片／MuPDF／OCR 的後續原生化維持相同引擎、版本及輸出等價要求，完成驗證後才切換。第三方完整對應來源核實缺口見 source/來源清單.json。
